# Contributing to glitchmonitor

Thank you for considering a contribution. glitchmonitor is developed by its
Stewards and published under the GNU Affero General Public License v3
(see [LICENSE](LICENSE)). Before your first contribution can be merged, you
must agree to the [Contributor License Agreement](CLA.md).

## Why there is a CLA

The Project is published under AGPL-3.0-or-later. The CLA lets the Stewards
keep the Project maintainable and lets them offer it under a commercial license
to organisations that cannot use the AGPL. You keep the copyright in your work.
The CLA grants the Stewards the rights they need; it does not transfer
ownership of your code to them.

Read [CLA.md](CLA.md) in full before you contribute. If you contribute on
behalf of an employer, check that your employer allows it.

## How to contribute

1. Open an issue first for anything larger than a small fix, so the approach
   can be agreed before you invest time.
2. Fork the repository and create a branch from `main`.
3. Make your change, with tests where behaviour changes, and run `make test`.
4. Open a pull request describing what changed and why.
5. Sign the CLA when prompted (see below).

## Code standards

- Follow the conventions in [CLAUDE.md](CLAUDE.md).
- Keep its decisions: one Go binary with the frontend embedded, no npm and no
  build step, and no CDN at runtime.
- Do not add dependencies without discussion. The project deliberately keeps
  them few, and frontend libraries are vendored into the binary.
- There are two ways to deploy, kustomize and Helm, and they must stay
  identical: make every manifest change in both `deploy/base` or
  `deploy/components` and `deploy/chart`. `make test` fails if they differ.
- Keep the legal notice in the dashboard footer, and if you run a modified
  version for others, build it with `SOURCE_URL` pointing at your source.
- Start every new source file (Go, JavaScript, CSS, HTML, YAML manifests, the
  Makefile, the Containerfile, scripts, workflows) with
  `SPDX-License-Identifier: AGPL-3.0-or-later` as a comment, after the shebang
  or the HTML doctype if there is one. In Go, leave a blank line after it, so it does not become
  part of the package documentation. No copyright line per file; the copyright
  is stated in [COMMERCIAL-LICENSING.md](COMMERCIAL-LICENSING.md).

## Third-party code

Only submit code you have the right to submit. If your change includes code
from another project, identify it and its licence in the pull request. The
licence must be compatible with AGPL-3.0-or-later.

## AI-assisted contributions

glitchmonitor is developed with the help of AI coding tools, and you may use
them too. The person who submits a change is its author for the purposes of
the [CLA](CLA.md): you have reviewed it, you understand it, and you take
responsibility for it as your own work.

- Say so in the pull request when a substantial part of your change was
  generated by an AI tool.
- Only submit AI-generated material that you have the right to submit under
  the CLA, and check that it does not reproduce third-party code.
- Record assistance in the commit message with an `Assisted-by:` trailer, for
  example `Assisted-by: Claude (Anthropic)`. Do not use `Co-Authored-By:` for
  a tool: a tool is not an author and cannot agree to the CLA.
